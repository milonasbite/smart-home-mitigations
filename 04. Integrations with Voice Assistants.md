# Attack vector: Integrations with Voice Assistants

| **Primary threat ** | **Zero Trust Policy** | **Mitigations to be applied a smart home owner** |
| :---                      | :---:                 |  :---:                                           |
|                           |                       |                                                  |
| Compromise via over sharing of information with voice assistants, such as your personal information | Sharing information on a need to know basis  | Before sharing information or chatting, please check if you need to do so with the voice assistant |
|                           |                         |
| Compromise via over sharing of information with voice assistants, such as payment cards | Authentication before authorisation | Make sure you have PIN enabled on your voice assistants for making purchases |
|                           |                         |
| Compromise via over sharing of information with voice assistants, such as emails and calendars | Sharing information on a need to know basis | Before asking any voice assistants to read your emails and/or calendar entries, please keep in mind that there may be phishing emails or malicious calendar entries which can harm smart home environments |

## Troubleshooting: VACA / View Assist announcements stop working

### Symptom

VACA still works normally as an Assist satellite when activated by wake word. For example, asking a question such as "what is the time?" produces a spoken response, and other Assist satellites continue to work. However, calls to `assist_satellite.announce` for the VACA satellite fail with an `Unknown error`.

The Home Assistant raw log may show:

```text
homeassistant.components.assist_satellite.errors.SatelliteBusyError
```

### Cause

Home Assistant believes that the VACA Assist Satellite is already processing an announcement. The satellite's internal announcement state can become stuck, causing subsequent `assist_satellite.announce` calls to be rejected as busy even though normal wake-word Assist requests still work.

### Solution

Reload the VACA integration in Home Assistant:

1. Go to **Settings → Devices & services → VACA**.
2. Open the integration menu and select **Reload**.
3. Test `assist_satellite.announce` again.

This resets the stuck Assist Satellite state. On 16 August 2026 this restored announcements immediately, and repeated announcement calls worked normally afterwards.

If a reload option is unavailable, restarting Home Assistant Core should also recreate the satellite entity and clear the stuck state.

### Debug logging

To temporarily enable useful logging while investigating the issue, run the following from **Developer Tools → Actions**:

```yaml
action: logger.set_level
data:
  custom_components.vaca: debug
  homeassistant.components.assist_satellite: debug
  homeassistant.components.wyoming: debug
```

After troubleshooting, restore normal logging with:

```yaml
action: logger.set_level
data:
  custom_components.vaca: warning
  homeassistant.components.assist_satellite: warning
  homeassistant.components.wyoming: warning
```
